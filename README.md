# Rassvet v0.1

Веб-приложение для управления расписанием учебного центра. Включает систему аутентификации, модерацию отзывов, новостной раздел через CMS и полноценную admin-панель для составления расписания.

---

## Стек

| Сервис | Технология | Порт |
|---|---|---|
| Backend API | Go 1.24 + Gin | 8080 |
| Frontend SPA | React 19 + MUI v7 | 3000 |
| База данных | PostgreSQL 15 | 5433 (хост) / 5432 (внутри контейнера) |
| Кэш / сессии | Redis 7 | 6379 |
| CMS | Directus 10.8 | 8055 |

---

## Быстрый старт

```bash
# Первый запуск
docker-compose up --build

# Повторный запуск
docker-compose up

# Только backend (без фронтенда)
docker-compose up postgres redis backend

# Пересобрать конкретные сервисы
docker-compose up --build backend frontend

# Логи backend
docker-compose logs -f backend

# Подключение к БД
docker exec -it postgres psql -U postgres -d reviews_db
```

После запуска:
- Frontend: http://localhost:3000
- Backend API: http://localhost:8080/api
- Directus CMS: http://localhost:8055
- Статический сайт: http://localhost:8080/main

Переменные окружения хранятся в `./backend/.env`.

## Архитектура

### Backend (Go)

```
cmd/main.go                        — инициализация, маршруты, CORS
internal/config/config.go          — загрузка env
internal/database/                 — PostgreSQL (GORM) + Redis
internal/middleware/auth.go        — JWT + AdminMiddleware
internal/models/                   — GORM-модели (22 структуры)
internal/handlers/                 — HTTP-хендлеры
internal/services/
    schedule_generator.go          — алгоритм генерации расписания (~700 строк)
    schedule_validator.go          — проверка конфликтов слотов
    email.go                       — SMTP-отправка
internal/utils/jwt.go              — генерация / валидация токенов
```

Хендлеры работают с `*gorm.DB` напрямую — без repository-слоя. Services-слой используется только для сложных алгоритмов. Маршруты регистрируются вручную в `main.go`.

### Frontend (React)

```
src/services/       — API-клиенты (axios)
src/pages/          — страницы (роуты)
src/components/     — переиспользуемые компоненты
src/App.js          — роутинг + стейт аутентификации
```

JWT хранится в `localStorage`. Axios interceptor автоматически добавляет `Authorization: Bearer <token>`. При 401 — редирект на `/login`. Защита роутов через `<PrivateRoute>` и `<AdminRoute>`.

## Функциональность

### Реализовано

**Аутентификация и пользователи**
- Регистрация с подтверждением email (код → Redis → создание пользователя)
- Вход / выход, JWT (24 ч), role-based access (`user` / `admin`)
- Восстановление пароля через email (временный пароль отправляется на почту)
- Обновление профиля (ФИО, email с повторной верификацией)

**Отзывы**
- CRUD отзывов с модерацией (`pending` → `approved` / `rejected`)
- Один пользователь — один активный отзыв
- Анонимный режим

**Новости**
- Новостной раздел через Directus CMS (фронтенд обращается к Directus напрямую)

**Модуль расписания — Настройка**
- Предметы, кабинеты, преподаватели, ученики — полный CRUD с деактивацией (toggle Пауза/Возобновить)
- Привязка предметов к кабинетам (M2M `room_subjects`)
- Привязка предметов к преподавателям (M2M `teacher_subjects`)
- Привязка кабинетов к преподавателям (M2M `teacher_rooms`) с флагом `is_strict` (строгий / предпочтительный)
- Окна доступности преподавателей и учеников (по дням недели, поддержка вс. — 1–7)
- Назначения (ученик + преподаватель + предмет): тип финансирования per-назначению, 1–5 занятий/нед., пауза/возобновление
- Групповые занятия: зачисление учеников, week overrides (замена преподавателя, количество занятий)
- Переопределения назначений на конкретную неделю (`assignment_week_overrides`)

**Модуль расписания — Генерация**
- Жадный алгоритм с многоуровневой приоритизацией:
  1. Тип финансирования **назначения** (платник > бюджетник) — per-subject, не per-student
  2. Строгие кабинеты (меньше гибкости по кабинетам)
  3. **EDF-сортировка**: суммарное доступное время ученика с преподавателем по всем дням недели — меньше = вперёд (ученики с узкими окнами ставятся первыми, чтобы не упустить их временной слот)
  4. Больше занятий в неделю
  5. Длиннее занятие
- Скоринг кандидатов: уплотнение расписания, бонус за раннее время, штраф за большие окна
- Буфер 5 минут между любыми двумя занятиями
- Учёт индивидуальных и групповых занятий, `is_strict` кабинетов, week overrides
- Поддержка воскресенья (день 7) в генерации и окнах доступности

**Модуль расписания — Управление результатом**
- Просмотр расписания с фильтрами (ученик, преподаватель, кабинет, тип финансирования)
- Цветовая маркировка слотов: красный = платник, синий = бюджетник, зелёный = группа
- Утверждение / сброс авто-части расписания (ручные слоты сохраняются)
- Ручные слоты с проверкой конфликтов: при создании и редактировании показывает список пересечений и предлагает удалить конфликтующее занятие
- Pause/resume отдельных назначений
- Исключение ученика из конкретного группового слота

**Диагностика генерации**
- Проблемы генерации разделены на 2 категории: ошибки конфигурации (оранжевые) и конфликты расписания (красные)
- Подробные диагностические сообщения: нет кабинетов для предмета, нет окон у преподавателя, нет пересечения расписаний, все слоты заняты и т.д.
- Фильтры по ученику, преподавателю, типу финансирования
- Сортировка по ученику/группе, преподавателю, предмету, причине

### Известные ограничения

- Нет публичной страницы расписания для учеников (только admin-панель)
- Нет UI для переопределений назначений на неделю (`assignment_week_overrides`)
- JWT не инвалидируется при logout (нет blacklist в Redis)
- Списки без пагинации и серверного поиска
- Жадный алгоритм без отката: плохое раннее решение не пересматривается
- Нет транзакции в генераторе: частичный сбой оставит неполные данные в БД

## API

Все эндпоинты с префиксом `/api`. Защищённые маршруты требуют `Authorization: Bearer <jwt>`. Admin-маршруты дополнительно проверяют `role == "admin"`.

### Публичные

| Метод | URL | Описание |
|---|---|---|
| POST | `/register` | Регистрация, отправка кода на email |
| POST | `/verify-email` | Подтверждение кода, создание пользователя |
| POST | `/resend-code` | Повторная отправка (cooldown 60 с) |
| POST | `/login` | Вход, возврат JWT |
| POST | `/forgot-password` | Запрос сброса пароля |
| POST | `/reset-password` | Сброс пароля по коду, отправка нового пароля на email |

### Для авторизованных пользователей

`GET /me`, `PUT /profile`, `POST /logout`, CRUD своих отзывов.

### Admin `/api/admin/...`

Полный CRUD для: предметов, кабинетов, преподавателей, учеников, назначений, групповых занятий, расписания и слотов. Модерация отзывов.

## База данных

PostgreSQL содержит таблицы приложения **и** конфигурацию Directus CMS. Категорически запрещено выполнять `DROP DATABASE`, `DROP SCHEMA public CASCADE` или удалять docker-volume `postgres_data` — конфигурация Directus не восстанавливается без ручной перенастройки.

GORM AutoMigrate запускается при старте приложения и автоматически добавляет новые колонки.
