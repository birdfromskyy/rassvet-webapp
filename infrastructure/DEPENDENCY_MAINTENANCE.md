# Обновление зависимостей

Состояние зафиксировано 19 сентября 2026 года. Production обновляется только
после отдельной проверки и резервной копии; этот документ относится к локальной
подготовке проекта.

## Закреплённые ветки

- Go toolchain: `1.27.1`;
- Node.js: `24.21.0` LTS (`frontend/.nvmrc`);
- PostgreSQL: `15.19` на прежней Debian-базе, без смены libc и без
  major-миграции существующего volume;
- Redis: `7.4.11`, с сохранением AOF;
- Nginx frontend image: `1.30.5` stable;
- Alpine runtime: `3.23`.

Точные версии инструментов сборки и библиотек фиксируются lock-файлами.
Образы обновляются осознанно: плавающие `latest` не используются.

## Регулярный процесс

1. Dependabot раз в месяц создаёт отдельные PR для Go, npm и Docker.
2. Major-обновления рассматриваются отдельно и не объединяются с обычными
   patch/minor-обновлениями.
3. Перед принятием обновления запускаются `go test ./...`, `go vet ./...`,
   `govulncheck ./...`, `npm test`, `npm run build` и полная Compose-сборка.
4. Изменение major-версии PostgreSQL требует dump/restore либо `pg_upgrade` и
   отдельной проверки восстановления. Обновление Redis требует проверки AOF и
   сценария отката.
5. Production не получает зависимости непосредственно из Dependabot PR:
   сначала изменения проверяются локально, затем проходят будущий CI и только
   после явного решения попадают в `main`.

## Известное исключение

`exceljs@4.4.0` остаётся необходимым для текущего браузерного экспорта и тянет
устаревший `uuid`. npm audit классифицирует две связанные находки как moderate;
безопасной совместимой версии ExcelJS пока нет. Принудительная подмена
транзитивной зависимости или downgrade ExcelJS не применяются, поскольку это
может повредить формирование XLSX. Риск должен исчезнуть после переноса
генерации документов в Desktop либо выхода исправленной версии ExcelJS.
